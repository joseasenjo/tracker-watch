Filter lists

Our list of tracking services, as a file for the ad and tracker blocker you already use.

What this is. A text file of domains. By itself it does nothing: it only takes effect when a blocker such as uBlock Origin or AdGuard reads it, and then that blocker stops other sites' requests to those domains. It is not complete protection: our list is limited, and blocking can change how a page works.

Why use a blocker at all

A blocker such as uBlock Origin (free, open-source, made by an independent developer) is an extension that checks each request your browser is about to make against lists of filters and stops the ones that match. Reading our list is one way to feed it. What a blocker gives you:

  • Fewer ads and fewer trackers contacted. Requests that match a filter never leave your browser, so those services are not contacted from your computer.
  • Pages that often load faster and use less data. A blocked request is a download that never happens. How much you save depends on the site: our blocking-list test measures the drop in third-party requests and data on the sites we measure.
  • Control per site. If a page stops working, you can pause the blocker on that one site and leave it on everywhere else.

How to use it

  1. Copy the address of the file you want (it only works once this site is published): {% for f in filters %}
    {{ site_base }}data/{{ f.file }}{% endfor %}
  2. uBlock Origin: open its dashboard, go to Filter lists, scroll to Import…, paste the address and press Apply changes.
  3. AdGuard (extension or app): Settings → Filters → Custom filters → Add custom filter, paste the address.
  4. Keep your blocker's usual lists as well: this one is a small, focused addition, not a replacement.

The file is for blockers that read Adblock syntax. A version for DNS-level blockers can be added if people ask for it.

What it includes, and what it leaves out

  • Only the tracking categories: advertising, analytics, social networks, session replay and audience measurement.
  • Never tag managers, consent tools or paywalls, because blocking them breaks sites (and our own banner test needs the consent tools to work).
  • Every rule is ||domain^$third-party: it covers the domain and its subdomains, but only when another site requests it. Visiting a company's own website, or using its own tools, is not affected.
  • The verified file holds only the entries whose operator we verified one by one. The full file adds the entries identified from general knowledge of the vendor and marked as unverified on the method page, which are listed separately at the end of the file. A wrong attribution there would block a harmless domain, so the verified file is the cautious choice.

What to expect

  • Blocking trackers sometimes breaks videos, comments, embedded content or log-ins. If a site stops working, pause the blocker on that site. Our blocking-list test shows how much third-party traffic a public list removes on the sites we measure.
  • We receive nothing from any blocker or browser, and naming them is not an endorsement.
  • Found a mistaken entry? Tell us and we will check it and fix the list.
